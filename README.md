# QuietSpace — 크롬북용 개인 웹 작업 공간

HTML·CSS·순수 JavaScript로 만든 정적 웹 앱입니다. 설치, 빌드, 서버 없이 HTTPS 정적 호스팅(GitHub Pages, Render)에서 실행됩니다.

> 이 앱은 **앱 내부에서** 방문 기록을 만들거나 저장하지 않습니다.
> Chrome 방문 기록, Google 계정의 웹 및 앱 활동, 학교 기기 관리·네트워크 기록에는 영향을 주지 않으며 이를 막거나 숨기지 않습니다.

## 파일 구성

| 파일 | 역할 |
|---|---|
| `index.html` | 앱 전체(화면, 스타일, 스크립트). 핵심 기능은 모두 이 파일에 있습니다. |
| `sw.js` | PWA 서비스 워커. 앱 자체 파일만 캐시합니다. |
| `manifest.webmanifest` | PWA 설치 정보 |
| `icons/` | 앱 아이콘(SVG, PNG) |
| `render.yaml` | Render 정적 사이트 설정(보안 헤더 포함) |

## 1. 구현된 기능

**메인 화면**
- 로고와 이름, 주소 입력창, 이동 버튼, 홈·잠금·설정 버튼
- 바로가기(타일)와 즐겨찾기(목록): 사용자가 직접 등록한 항목만 표시합니다.
- 보안 및 저장 정책 카드: 현재 상태(Web Crypto, PIN 잠금, 자동 잠금 시간, 격리 iframe, 오프라인 사용 여부)와 앱이 제어할 수 없는 영역을 보여 줍니다.
- 다크 모드(기본), 라이트 모드, 시스템 설정 따르기
- 반응형 레이아웃, 키보드 조작, 포커스 표시

**주소 검증**
- `https:`만 허용합니다. 프로토콜 없이 입력하면 `https://`를 붙입니다.
- `http:` 주소는 HTTPS로 바꾸고 알려 줍니다. HTTPS 페이지 안에서는 HTTP 콘텐츠가 표시되지 않기 때문입니다.
- 거부하는 입력: `javascript:`, `data:`, `file:`, `blob:`, `chrome:`, `ftp:` 같은 프로토콜, 공백이 들어간 입력(검색어), 사용자 이름이나 비밀번호가 포함된 주소, 잘못된 도메인, 앱 자신의 주소

**방문 기록 저장 방지**
- 현재 주소는 메모리 변수(`state.currentUrl`)에만 둡니다. 잠금, 닫기, 초기화 시 iframe을 제거하고 주소 입력창을 비웁니다.
- 방문 목록, 최근 방문, 방문 분석 기능이 없습니다. 분석 도구, 광고, 외부 요청 코드도 없습니다.
- 사용자가 "저장"을 누른 항목만 PIN에서 유도한 키(AES-GCM)로 암호화해 `localStorage`에 저장합니다.
- 설정 → **저장 데이터 점검**: 이 사이트가 브라우저에 저장한 항목을 보여 주고, 평문 웹 주소가 섞여 있는지 확인합니다.

**웹사이트 표시(iframe)**
- `sandbox="allow-scripts allow-same-origin allow-forms"`를 적용합니다. 팝업은 설정에서 켰을 때만 허용합니다. `allow-top-navigation`을 주지 않아 사이트가 앱 주소를 바꿀 수 없습니다.
- `referrerpolicy="no-referrer"`를 적용합니다. Chrome이 지원하면 `credentialless` 격리 iframe도 사용합니다(설정에서 끌 수 있음).
- 12초 동안 응답이 없으면 안내를 보여 줍니다. 자동으로 다시 시도하지 않습니다.
- iframe 표시를 막는 것으로 알려진 사이트는 미리 경고합니다. YouTube 주소는 임베드 플레이어로 열 수 있게 제안합니다.
- 새 탭으로 열 때는 "Chrome 기록에 남을 수 있음" 확인을 거칩니다. 확인 없이 새 탭을 열지 않습니다.

**PIN 잠금**
- 첫 실행 시 PIN을 설정합니다(숫자 4~12자리, 반복·연속 숫자 거부).
- 잠금 해제, 수동 잠금(버튼 또는 `Alt+L`), 비활성 자동 잠금(기본 5분, 1~15분 중 선택), 다른 탭으로 전환하면 즉시 잠그는 옵션을 제공합니다.
- 5회 틀리면 30초 동안 입력을 막습니다. 이후 틀릴 때마다 대기 시간이 두 배로 늘어 최대 15분까지 됩니다.
- PIN 변경 시 즐겨찾기를 새 키로 다시 암호화합니다.
- PIN을 잊었으면 잠금 화면에서 "저장 데이터 초기화"로 복구합니다. 저장된 데이터는 모두 삭제됩니다.
- 잠금 상태에서는 앱 화면을 숨기고, 복호화한 즐겨찾기와 키를 메모리에서 지웁니다.
- 뒤로 가기로 페이지에 돌아오면(bfcache) 다시 잠깁니다.

**코드 보안**
- 문자열로 DOM을 만들지 않습니다(`innerHTML` 미사용). 모든 텍스트는 `textContent`로 넣습니다.
- CSP: 외부 리소스를 막고, `frame-src https:`, Trusted Types를 적용합니다.
- 다른 페이지 안에 삽입되면 실행을 거부합니다(클릭재킹 방지).
- 콘솔에 아무것도 출력하지 않습니다.

## 2. 알려진 제한

- iframe은 진짜 브라우저가 아닙니다. 뒤로/앞으로 이동, 탭, 다운로드, 알림, 일부 로그인·결제·동영상 기능이 작동하지 않을 수 있습니다.
- Google, GitHub, YouTube(일반 페이지), SNS 등 많은 사이트가 iframe 표시를 막습니다. 브라우저가 차단 여부를 앱에 알려 주지 않아 자동으로 판별할 수 없습니다.
- iframe 안에서 클릭하거나 입력해도 자동 잠금 타이머는 활동으로 보지 않습니다. 사이트를 오래 보고 있어도 설정한 시간이 지나면 잠깁니다.
- Chrome이 PIN 입력칸에 비밀번호 저장을 제안할 수 있습니다. 거절하면 됩니다.
- HTTPS가 아닌 환경에서는 Web Crypto를 쓸 수 없어 **제한 모드**로 실행됩니다. 이때 PIN을 쓸 수 없고 즐겨찾기는 저장되지 않으며, 화면에 그 사실을 표시합니다.
- 코드를 수정할 때 `innerHTML`이나 외부 스크립트를 추가하면 CSP와 Trusted Types 때문에 동작하지 않습니다(의도된 동작).

## 3. 학교 크롬북에서 설치 없이 실행하기

1. 아래 4번 방법으로 배포합니다.
2. Chrome에서 배포 주소(`https://...`)를 엽니다.
3. 처음 열면 PIN을 설정합니다.
4. (선택) 주소창 오른쪽 설치 아이콘이나 메뉴 → "앱 설치"로 PWA로 설치합니다. 학교 정책으로 막혀 있을 수 있습니다.

`index.html`을 파일로 직접 열어도 화면은 뜨지만 PWA는 동작하지 않습니다. 모든 기능을 쓰려면 HTTPS로 배포한 주소를 사용하세요.

## 4. GitHub 웹 화면만으로 저장소를 만들고 배포하기

**저장소 준비**
1. github.com → 오른쪽 위 `+` → **New repository** → 이름 입력 → **Public** → **Create repository**
2. **Add file → Upload files**에서 이 저장소의 파일(`index.html`, `sw.js`, `manifest.webmanifest`, `render.yaml`, `icons/` 폴더)을 끌어 놓거나, **Add file → Create new file**로 파일 이름을 입력하고 코드를 붙여 넣습니다(`icons/icon.svg`처럼 경로를 입력하면 폴더가 만들어집니다).
3. **Commit changes**를 누릅니다.

**A. Render로 배포**
1. render.com에 GitHub 계정으로 가입하거나 로그인합니다.
2. **New → Static Site**에서 저장소를 선택합니다.
3. 설정값:
   - Build Command: 비워 두거나 `echo "no build step"`
   - Publish Directory: `.`
4. **Create Static Site**를 누르면 `https://<이름>.onrender.com` 주소가 생깁니다.
5. 보안 헤더 적용: **New → Blueprint**로 이 저장소를 연결하면 `render.yaml`이 읽힙니다. 또는 사이트 설정의 **Headers**에 `render.yaml`과 같은 값을 직접 입력합니다.

> `render.yaml`은 Render Blueprint의 정적 사이트 형식(`runtime: static`, `staticPublishPath`, `headers`)으로 작성했습니다. 작성 환경에서 Render 문서에 접속하지 못해 최신 문서로 검증하지 못했습니다. Blueprint 연결에서 오류가 나면 대시보드에서 위 3단계 값과 헤더를 직접 입력하세요.

**B. GitHub Pages로 배포(대안)**
1. 저장소 → **Settings → Pages**
2. Source: **Deploy from a branch**, Branch: `main` / `/ (root)` → **Save**
3. 1~2분 뒤 `https://<사용자명>.github.io/<저장소명>/`에서 열립니다.
4. GitHub Pages에서는 응답 헤더를 직접 설정할 수 없습니다. 대신 `index.html`의 CSP meta 태그와 iframe 삽입 차단 스크립트가 같은 역할을 합니다.

## 5. 실제 테스트 체크리스트

- [ ] 첫 실행 시 PIN 설정 화면이 나온다.
- [ ] `1111`, `1234`, 서로 다른 확인값은 거부된다.
- [ ] 새로고침하면 PIN 입력 화면이 나오고, 앱 화면·즐겨찾기·설정은 보이지 않는다.
- [ ] 틀린 PIN을 5번 넣으면 30초 대기 안내가 나오고 입력칸이 비활성화된다.
- [ ] `javascript:alert(1)`, `data:text/html,x`, `file:///`, `hello world`, `ftp://x.com`은 거부된다.
- [ ] `example.com` → `https://example.com/`, `http://example.com` → HTTPS로 바뀌었다는 안내가 나온다.
- [ ] `https://ko.wikipedia.org`처럼 iframe을 허용하는 사이트가 표시된다.
- [ ] `https://www.google.com`은 사전 경고가 나오고, 빈 화면이면 안내 내용을 펼칠 수 있다.
- [ ] 새 탭 버튼을 누르면 확인 창이 나오고, 확인해야만 열린다.
- [ ] 저장 버튼 → 이름 입력 → 즐겨찾기에 추가된다. 방문만 한 사이트는 추가되지 않는다.
- [ ] 잠금 버튼 또는 `Alt+L`을 누르면 주소 입력창과 iframe이 비워진다.
- [ ] 5분 동안 조작하지 않으면 자동으로 잠긴다.
- [ ] 설정 → PIN 변경 후 새 PIN으로 해제되고, 즐겨찾기가 그대로 남아 있다.
- [ ] 설정 → 초기화(“초기화” 입력) 후 PIN 설정 화면으로 돌아간다.
- [ ] 라이트 모드 전환, 좁은 화면(휴대폰 폭) 레이아웃, Tab 키만으로 조작이 된다.
- [ ] 배포 주소에서 설치 아이콘이 보이고, 오프라인에서도 앱 화면이 열린다.

## 6. 방문 주소가 자동 저장되지 않는지 점검하는 방법

1. **앱 안에서**: 사이트 몇 곳을 연 뒤 설정 → **저장 데이터 점검**을 누릅니다. "평문 웹 주소 없음"이 나와야 합니다.
2. **개발자 도구로**(학교 정책으로 막혀 있을 수 있음): `Ctrl+Shift+I` → **Application** 탭에서
   - Local Storage: `quietspace:v1` 하나만 있고, 그 안의 `vault.ct`는 읽을 수 없는 암호문이어야 합니다.
   - Session Storage, IndexedDB: 비어 있어야 합니다.
   - Cache Storage `quietspace-v1`: 앱 파일(`index.html`, 아이콘, 매니페스트)만 있어야 합니다.
3. **Network 탭**: 사이트를 열 때 QuietSpace가 자기 서버나 다른 서버로 주소를 보내는 요청이 없어야 합니다(iframe이 그 사이트를 직접 불러오는 요청만 보임).
4. **코드 검색**: `index.html`에서 `fetch(`, `sendBeacon`, `XMLHttpRequest`, `indexedDB.open`이 없고, `localStorage.setItem`은 `writeStore()`와 저장소 사용 가능 여부 확인(`storageWorks()`, 임시 값을 쓰고 바로 삭제) 두 곳에서만 쓰이는지 확인합니다.

이 점검은 **앱의 저장소**만 확인합니다. Chrome 방문 기록(`Ctrl+H`)에는 앱 주소나, 새 탭으로 연 사이트가 남을 수 있습니다.

## 7. PIN 잠금의 실제 보호 수준과 한계

**막아 주는 것**
- 같은 기기를 잠깐 보는 사람이 앱 화면, 바로가기, 즐겨찾기를 바로 보는 것
- 자리를 비웠을 때 열려 있던 사이트가 계속 보이는 것(자동 잠금)
- 저장소를 그냥 열어 봤을 때 즐겨찾기 주소가 평문으로 보이는 것(AES-GCM 암호화)

**막지 못하는 것**
- 숫자 PIN은 경우의 수가 적습니다(4자리는 1만 가지). 저장소 내용을 복사한 사람은 재시도 제한 없이 오프라인으로 모든 경우를 시도할 수 있습니다. PBKDF2(SHA-256, 310,000회)는 속도를 늦출 뿐입니다.
- 재시도 제한 정보도 `localStorage`에 있어서, 개발자 도구로 지울 수 있습니다.
- 소스 코드 변경, 악성 확장 프로그램, 사이트 데이터 삭제로 우회되거나 초기화될 수 있습니다.
- 계정 인증이 아니며 서버 측 보호가 없습니다.
- Chrome, Google 계정, 학교 관리·네트워크 기록과는 무관합니다.

중요한 정보 보호에는 사용하지 마세요. 더 안전하게 쓰려면 PIN을 길게(8자리 이상) 설정하세요.

## 8. PWA 지원

- `manifest.webmanifest`: 이름, 아이콘(192/512, maskable), `display: standalone`
- `sw.js`
  - 설치 시 앱 파일 7개만 캐시합니다.
  - 앱 화면은 네트워크를 먼저 시도해 업데이트를 반영하고, 오프라인이면 캐시를 사용합니다.
  - 다른 출처 요청(iframe으로 연 사이트)은 가로채거나 캐시하지 않습니다.
- 서비스 워커는 HTTPS(또는 localhost)에서만 등록됩니다.
- 코드를 바꿔 배포했는데 아이콘 등이 갱신되지 않으면 `sw.js`의 `CACHE_NAME`을 `quietspace-v2`처럼 올리세요.
- 오프라인에서는 앱 화면만 열립니다. 외부 사이트는 당연히 열리지 않습니다.

## 9. 추후 Render 호스팅 계획

1. **지금**: GitHub Pages 또는 Render Static Site 중 하나로 배포합니다. 둘 다 무료 정적 호스팅이며 코드 변경이 필요 없습니다.
2. **Render로 옮길 때 얻는 것**: `render.yaml`의 응답 헤더(`frame-ancestors 'none'`, `X-Content-Type-Options`, `Referrer-Policy`, `Permissions-Policy`, `sw.js`의 `no-cache`)가 적용되어 GitHub Pages보다 보안이 조금 강화됩니다.
3. **자동 배포**: Render는 GitHub의 `main` 브랜치에 커밋하면 다시 배포합니다. GitHub 웹 화면에서 파일을 수정해도 바로 반영됩니다.
4. **사용자 지정 도메인**: 필요하면 Render 설정의 Custom Domains에서 연결합니다(HTTPS 인증서 자동 발급).
5. **범위**: 정적 사이트로만 운영합니다. 방문 주소를 서버로 보내거나 중계하는 서버 기능(프록시 등)은 추가하지 않습니다. 이 앱의 "서버로 주소를 보내지 않는다"는 원칙과 맞지 않기 때문입니다.
